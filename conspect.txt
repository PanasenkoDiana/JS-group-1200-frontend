правила створення компонентів у react 
1) усі компоненти назіваємо з великої літери
2) компонент повертає лише один корневий елемент
3) при створенні класу використовуємо className
4) при виразі джава-скріпту чи тайп-скріпту
 у середині jsx використовуємо фігурні дужки{}
5) теги без дочірнього вмісту закриваємо:
    <img /> <input />
props - данні які передаються від батьківського 
компоненту до дочірнього

react-hook-form - біблеотека для роботи з html формами у react.
    5 причин чому обирають саме R.H.F.:
        1 причина продуктивність - для продуктивності опирається на нативні html поля.
        2 причина зручний API - useForm, register, handleSubmit описують зрозумілий процес.
        3 причина TypeScript - тип форми допомагає виявляти помилки ще під час розробки.
        4 причина розширюваність - є інструменти для валідації, дінамічних полів та складніх UI компонентів.
        5 причина екосистема - підримує інтеграцію з ZOD та іншими валідаторами.

перерендеринг(Re-rendering) - це повторний запуск функції реакт компонента,щоб реакт знову перевірив
що потрібно відобразити на сторінці
Повторний рендер не дорівнює повному перезавантаженню сторінки,та не обов'язково призводить до зміненню DOM
Життєвий цикл реакт компонента - це його поява на сторінці,оновлення та видалення зі сторінки 
useEffect - реакт хук, який дозволяє виконати додаткові дії після того, як реакт відобразив компонент 
складається з 3 етапів:
    1) Mount(монтаж) - реакт вперше показує компонент на сторінці,у нашому випадку RegisterForm 
    2) Update(оновлення) - користувач вводить e-mail, RHF відстежує змінення значення поля 
    3) Unmount(розмонтування) - якщо RegisterForm чи окреме поле прибрати з JSX,
    реакт видалить відповідний елемент з DOM

npm i react-hook-form - встановлення бібліотеки RHF
